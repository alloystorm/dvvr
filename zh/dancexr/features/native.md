# DanceXR Native

**DanceXR Native** 是一款独立的 Windows 应用程序，旨在以你的 PC 所能达到的最高画质渲染角色：在支持光线追踪的硬件上使用完整的**路径追踪**，其余情况则使用**光栅渲染器**。它是专为基于 Unity 的 DanceXR 运行时打造的配套应用，拥有自己的渲染器和设置，同时使用同一套整理好的内容库。

Native 于 2026.8 进入公开预览，并在支持 PMX 模型、多角色场景与 OpenXR VR 后，于 [2026.9](../releases/2026.9) 正式发布。**[2026.10](../releases/2026.10)** 新增了光栅渲染器、图形设置自动检测、布料、Wet Skin & Fluid、自动相机，以及无需重启即可进入的 VR。

下载：[github.com/alloystorm/dvvr/releases/tag/dxr-native](https://github.com/alloystorm/dvvr/releases/tag/dxr-native)

## 一个应用，两种渲染器

Native 在同一个应用程序中同时包含路径追踪器和光栅渲染器。首次启动时，它会测量你的 GPU 并为你选择渲染器和画质级别，因此开始之前无需任何配置。可随时在 **System > Graphics** 中使用 **Detect best settings** 重新检测。

### 路径追踪带来什么

DanceXR 的 PC RT 版本是在传统渲染器之上叠加光线追踪效果（参见[光线追踪效果](raytracing)）。Native 的路径追踪器选择了另一条路：整幅画面都由路径追踪生成，光照是被模拟出来的，而不是近似出来的。

- **真实的光线弹射** —— 被灯照亮的墙面会把带颜色的光投到附近的面孔上，无需探针，也无需烘焙。
- **柔和阴影**，带有真实的半影，并随着与遮挡物的距离而扩散。
- **真实的反射** —— 表面反射的是房间里实际存在的东西，包括画面外或摄像机背后的物体。
- **体积雾与光束** —— 雾层直接内建于路径追踪器中，因此光柱与丁达尔效应来自真实的光线传播。

两种渲染模式：

- **实时** —— 经过降噪与超分，达到可交互的帧率。摆姿、构图与播放都在这个模式下进行。
- **参考** —— 用数秒时间累积采样，得到干净无噪点的画面，适合出静态图。

### 光栅渲染器

光栅渲染器面向路径追踪过慢或完全不可用的 PC，包括集成显卡。它共用相同的场景、角色、材质和物理，因此在一种渲染器中搭建的场景可以在另一种中打开。

- 阴影、环境光遮蔽与环境光照，并带有时间性抗锯齿。
- **DLSS 与 FSR 超分辨率**，因此不支持 DLSS 的 GPU 也可以进行超分。
- 在支持光线追踪的 GPU 上，可选的**光线追踪阴影、反射和全局光照**能以很小的开销让画面更接近路径追踪器。
- 面向 MMD 风格模型的**卡通与无光照着色**，详见下文的材质部分。

在 **System > Graphics** 中选择渲染器。在路径追踪器与光栅之间切换会重启 Native，并恢复你的场景。

### 光栅画质档位

在光栅模式下，**Raster quality tier** 决定整体级别：

| 档位 | 使用的内容 |
|---|---|
| High | 环境光遮蔽，加上光线追踪阴影、反射和全局光照 |
| Mid | 环境光遮蔽，加上光线追踪阴影和反射 |
| Low | 环境光遮蔽与阴影贴图 |
| Toon | 所有材质以卡通着色显示，使用阴影贴图 |
| Minimal | 所有材质以无光照方式显示，面向最弱的硬件 |

如果某个档位要求的功能你的 GPU 无法实现，Native 会自动回退，并告诉你它更改了什么。

## 运行要求

| | |
|---|---|
| 操作系统 | Windows |
| 显卡（光栅） | 支持 DirectX 12，包括集成显卡 |
| 显卡（路径追踪） | 支持光线追踪的独立显卡（推荐 NVIDIA RTX） |
| VR | 兼容 OpenXR 的头显与运行时 |

如果你的显卡无法运行路径追踪器，Native 会以光栅模式启动，而不会拒绝启动。

## 支持的内容

这是下载前最需要了解的一点。

- **模型：PMX 与 XPS / XNALara**（`.pmx`、`.xps`、`.mesh`、`.ascii`），可以是单独文件或 ZIP 压缩包。包含多个 PMX 模型的 ZIP 可让你选择要加载的模型。
- **动作：VMD**（MikuMikuDance），包含镜头动作。
- **视频**：内容库 `videos` 文件夹中的视频，用于房间的视频墙。

PMX 支持包括附加与继承骨骼变形、IK、顶点/骨骼/材质/组变形以及刚体物理。表情变形可以由 VMD 动作驱动，也可在 Actors 菜单中调节。

XPS 模型与 PMX 模型以相同的方式适配动作，因此双脚会稳稳踩在地面。XPS **换装分组**可开关可选的服装部件，**骨骼映射**编辑器可修复骨骼未被自动识别的模型。

还没有自己的模型？可从 **Actors > Load** 加载内置的 **Dummy** 来试用动作。

### 版本与角色数量限制

免费版一次可渲染**一个角色**。加载第二个模型会替换掉第一个，应用会在此时给出提示。已激活的 Pro 安装支持同时使用多个角色，每个角色都可拥有自己的模型设置、材质、物理、位置与动作。在 Pro 中，**Load mode** 开关用于选择新模型是替换现有阵容还是加入其中。

Pro 还可解锁下文介绍的 Wet Skin & Fluid。

## 使用方式

拖放是主要的操作入口——把模型、动作或 ZIP 拖到窗口上即可加载。界面分为 **Actors**、**Motion**、**Camera**、**Environment**、**Scene** 与 **System** 几个标签页。滑块带有 -/+ 按钮、鼠标滚轮调节，以及用于输入精确数值的数字键盘。

Native 会在多次启动之间记住你的系统设置，并恢复上次会话。如果该会话中的某些内容导致 Native 在启动时崩溃，下次启动会跳过它而不会再次崩溃。

### 摆姿与动作

- 带音频的 VMD 动作播放，通过共享时钟保持同步。
- 播放模式：单曲、单曲循环、列表、列表循环和随机播放。
- **随机播放**会挑选下一支舞蹈或换入另一位演员，并根据你的观看习惯学习。
- 逐动作的音乐偏移、静止姿势（包括 T 姿势）以及 **Center pivot** 设置，后者用于修正由游戏骨架转换而来的动作。这些设置会应用于使用该动作的每个角色。
- 没有播放动作时的程序化待机动作，以及可以看向摄像机的眼神接触。带有眼睑骨骼的角色会眨眼，眼睑也会随视线移动。
- 腿部 IK 与双脚贴地解算，让脚稳稳落在地面上，而不是悬浮或下陷。

### 物理

- 头发、衣物和软体物理被整理为**具名分组**，每组都有独立的调节参数、开关和预设。设置分组时可直接在视口中拾取骨骼。
- 身体碰撞体，以及由 PMX 定义的刚体物理。
- 可从任意角色的 Physics 菜单为其添加**布料服装**。裙子会自动贴合腰部，与身体发生碰撞，并附带可自行扩充的预设。

### Wet Skin & Fluid（Pro）

水滴落在角色身上，沿身体流下、汇合，并在身后留下湿润的痕迹。水滴会响应角色自身的动作，因此快速挥动会把水带向肢体末端，甚至将其甩出。它可同时作用于皮肤和衣物，并带有湿发效果，设置会随每个模型保存。

### 相机

- 自由飞行相机与环绕相机，以及 VMD 镜头动作。
- **自动相机**会按节拍将舞蹈切分为多个镜头，可调节节奏、运动、角度以及相机的远近。
- 使用 Motion 菜单中的 **Tap beat** 设置歌曲速度，或直接输入 BPM 和节拍偏移。节拍信息会按歌曲记忆。

### 摆放角色

把鼠标移到角色脚下会出现交互圆盘：拖动可在地面上移动，滚轮可旋转。这个圆盘是真正的自发光几何体，它的光会实际照亮角色。

### 场景与房间

默认环境是一个程序化房间，带有真实的窗户开口、可调节的照明与体积雾。它的正面墙可以是**练习镜**，也可以是与音乐同步播放的**视频墙**（受光屏幕或 LED 墙）。场景可以按名称保存和重新加载，并保留完整的角色阵容、位置、材质与动作分配。

灯光可以重复排列为扇形、网格或一排，聚光灯还可以自动跟随你的演员。

### 材质

可逐材质调整粗糙度、金属度、各向异性与次表面散射，并支持按名称分组重映射，让你一次性调整所有「hair」材质。皮肤、头发和服装分组还提供整组的次表面散射、表面细节和可见性控制。

在光栅模式下，每个材质都有一个着色模型——**Lit、Toon 或 Unlit**——可按材质、按分组或对整个角色设置。Toon 使用模型自带的卡通渐变、球面贴图和描边。

### VR

- 可在 **System > VR** 中无需重启即进入和退出 VR，也可以从 DanceXR Launcher 以 VR 模式启动 Native。
- 桌面和 VR 各自保存图形设置，每个头显也保存自己的设置。首次 VR 会话会在约十秒内自动调优。
- **注视点路径追踪**降低视野边缘的开销，并在支持眼动追踪的头显上跟随你的视线。
- 可选择 Native 使用的 OpenXR 运行时，而无需更改 PC 的默认设置。
- 按键可以在 VR 手柄、游戏手柄和键盘之间重新映射。

## 反馈问题

Native 会为每次会话写入日志，崩溃时还会保留转储文件。**System** 标签页中提供 **Report Issue**、**Copy Diagnostics** 与 **Open Log**。反馈问题时请附上日志。
